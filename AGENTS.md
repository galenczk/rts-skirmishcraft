# Contributor Instructions

These instructions apply to the entire repository.

## Prototype discipline

- Do not invent gameplay mechanics.
- When gameplay intent is ambiguous, preserve flexibility and report the ambiguity.
- Prefer the simplest implementation capable of testing the current prototype hypothesis.
- Avoid speculative architecture and unnecessary abstractions.
- Do not add third-party packages without explicit approval.
- Use primitive placeholder assets.
- Keep gameplay logic reasonably separable from presentation when straightforward.
- Build after meaningful code changes.

## Task completion report

At the end of every task, report:

1. Files changed.
2. Behavior implemented.
3. Technical assumptions.
4. Game-design assumptions.
5. The recommended next verification step.
